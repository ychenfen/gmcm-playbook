# 去 AI 味与润色流程

附件4 第 2 条要求论文文字「必须使用参赛队自身的语言进行表述」。所以去 AI 味不只是为了好读，也是合规要求。最稳的做法是：队员先弄懂内容，再用自己的话写；AI 最多帮忙查错、理顺句子。

## 一、改稿顺序（每写完一节做一遍，不要攒到最后）

1. 先把内容写实。能写数字就不写「显著」，能写具体失败原因就不写「具有一定局限性」，边界条件写到具体用例或参数。只写真实发生过的事，不要为了降低检测分编造经历、错误或局限。
2. 再改表达。只改句子，不动数字、公式、引用、算法名，也不动 AI 使用说明段。
3. 跑检查脚本：`python3 工具/paper_lint.py 你的论文.tex`。D、G 两类问题（论断、合规）终稿前必须清零，其余类别逐条看，有理由的可以保留。
4. 队员通读一遍。读的时候问自己：这一段评委要是当面问，我能不能讲清楚？讲不清的就是没吃透，要回去改内容，不是改措辞。

## 二、红线

- 不改变技术含义。
- 不把「我们不确定」改成确定的语气。
- 不删边界条件和限定词，不为了句子通顺把「在 X 条件下」合并掉。
- 不编造引用。所有参考文献都要能查到原文。

## 三、常见 AI 腔和替换方向

| AI 腔 | 问题 | 怎么改 |
|---|---|---|
| 值得注意的是、不难发现、由此可见、综上所述、基于以上分析 | 空转的连接词 | 直接删，看句子是否照样成立（通常成立） |
| 具有重要意义、具有广泛的应用前景、为……提供了新思路 | 无法验证的套话 | 写具体用途，或者删掉 |
| 显著提升、有效降低、大幅改善 | 没有数字的程度词 | 同一句里给出数字：「降低 18.3%（从 X 到 Y）」 |
| 首创、突破性、卓越、充分证明 | 过度宣称 | 删；需要强调时用对比数字 |
| 首先……其次……最后…… | 八股排比 | 按逻辑关系写：因为、所以、但是、在此基础上 |
| 每句一样长、每段都是总分总 | AI 文本的节奏特征 | 长短句交替；有的段落直接从结论开始 |
| 大量加粗、大量列表 | 像 PPT，不像论文 | 正文以段落为主；列表只用于真正并列的条目 |
| 深入探讨、全面分析、协同、赋能 | 抽象大词 | 换成具体动作：比较了哪些方法、改了哪个参数 |

## 四、写出「人味」靠内容，不靠措辞

- 至少写一处取舍：为什么选了 A 没选 B，B 试过的话结果如何。
- 至少写一处局限：模型在什么数据、什么参数下不成立，最好给出具体用例。
- 用具体数字代替模糊的描述。
- 句子有长有短，不要每句都是「主语 + 通过 + 方法 + 实现了 + 效果」的格式。

2025 年 A 题四篇优秀论文正文的虚词密度（每万字里套话和程度词的次数）从 16.9 到 37.1 不等，`paper_lint.py` 以最低的 16.9 为目标。这个数只是参考，不是评分标准。
