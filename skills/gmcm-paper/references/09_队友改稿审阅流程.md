# 队友改稿审阅流程（Word/WPS）

2026A 的最后三天基本花在"队友改一版 → 审阅修复 → 再改一版"上。下面这套做法能让每一轮控制在一小时以内。

## 每次收到新稿

1. **原件留档**：按"来源_时间"命名（例如 `队友改写_1834.docx`），记录 SHA256，永远不在原件上改。
2. **体检**：`python3 scripts/docx_tools.py stats 新稿.docx`，和上一版比较公式、图片、表格、批注数。数量变了要先查清原因。
3. **逐段 diff**：抽出两版的段落文本，按相似度配对，列出所有改动（本仓库案例用的是 difflib，生成 `diff_pairs.txt`）。重点查：
   - 机械替换：例如"题目附录 B"被改成"附录 B"（指向就错了）、"官方配置"被改成"配置"；
   - 逻辑被改反，例如把"不一定是最优解"改成"即精确求解"；
   - 为了去掉"我们"删了主语，结果句子没有主语；
   - 数字、公式编号、图表编号被改动；
   - 代码清单被改动；
   - AI 说明被改得和事实不符。
4. **修复**：只修错误，队友合理的改写全部保留。修复稿另存新名，写进 MANIFEST。
5. **给队友反馈**：直说哪里改错了、为什么。队友问"我改的对不对"时，就给具体结论。

## 批注版

- 每条批注都要给出决定：采纳，或不采纳并说明理由。例如：
  - "本文→本研究"不采纳：没有实质区别，改了反而和其他章节不统一；
  - "删附录源码"采纳：附件程序已单独提交。
- 处理完后删除批注：`docx_tools.py strip-comments`。然后清属性：`clean_meta.py`。

## 修改 docx 的技术坑

- 文本常被拆在多个 `w:t` 节点里，替换前要合并同一段的文本再定位。**不要让替换范围跨过公式对象（`m:oMath`）**，否则公式会被删掉。
- WPS 稿里常有不间断空格 `\xa0`，按普通空格匹配会找不到。
- 给子串加粗：把 run 拆成三段，中间一段设为 bold，并复制原 run 的 rPr。
- 属性顺序：新增 `w:rPr` 子元素时要遵守 OOXML 的元素顺序，否则 Word 会报文件损坏。
- 目录单独成页：在目录 SDT 前插入分页段（`docx_tools.py toc-break`），然后在 WPS 里更新目录。
- WPS 导出 PDF 时会把账号昵称写进 Author，必须用 `clean_meta.py` 清掉。

## 定稿导出前（队友操作）

1. 右键目录 → 更新域 → 更新整个目录。
2. 文件 → 属性，作者清空。
3. 导出 PDF，文件名按平台要求命名（常见是队号）。
4. 发回后跑 `submission_check.py`。
