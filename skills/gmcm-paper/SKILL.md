# 华为杯数模：从题目到提交

来源：2026 年第二十三届 A 题（多核 NPU 切图调度）完整做过一遍的经验。案例代码与论文源码在本仓库 `case-2026A/`，复盘在 `LESSONS.md`。

## 五条总原则

1. **官方评估程序和官方数据是唯一真相。** 正文、表格、摘要里的每个数字都由脚本从评估结果生成，不手抄。LaTeX 用 `\V{键名}` 宏，Word 稿在定稿前一次性生成。
2. **先做实结果，再写论文。** 设一个结果冻结点，冻结后只修错误、不改模型。数字不定就动笔写，改一次模型就得改一遍全文。
3. **只保留一个主稿。** 第 3 天前定下以 LaTeX 还是 Word/WPS 为主稿。队友接手 WPS 以后，WPS 稿就是主稿，LaTeX 只作参考，不再维护两套。
4. **AI 使用如实说明。** 附件4 要求写明工具、版本、开发机构、颁布日期、用途和人工核验情况，程序文件开头也要注明。队友每次回传都要重新核对附录的 AI 说明。
5. **完成状态分层报告。** 本地生成、本地验证、上传、平台显示"已提交"是四个不同的状态。只有平台显示已提交才算交了。

## 时间线（5 天赛程，按 2026 年实际调整）

| 时间 | 做什么 | 验收门槛 |
|---|---|---|
| D0 上午 | 读题、附件2/3/4、官方材料包；列出"必须交付"清单（每问要求的图、附录表、程序输入输出格式） | 清单逐条对应题面原文 |
| D0 下午 | 数据刻画：规模、结构分类、理论下界；跑通官方评估程序；做强基线（不用稻草人） | 基线数字由评估程序给出 |
| D1–D2 | 多种构造方法 + 参数网格 + 逐用例选优；负面结果照记；算力不够就租按量服务器 | 全量矩阵跑完、0 失败 |
| D2 晚 | **结果冻结**：finalize 复评、方案哈希、可复现性核对、独立恢复副本 | 复评值逐位等于扫描记录 |
| D3 | 写论文：按获奖论文的目录骨架；命题带证明；自己提出的公式后面补推理 | 编译 0 错误、数字全由宏生成 |
| D3 晚–D4 上午 | 转 Word/WPS、队友通读改写、批注逐条处理 | 公式/图/表数量前后一致 |
| D4（截止前 2 小时） | 提交包：PDF 清属性、`submission_check.py`、附件程序 zip、SHA256、备份；上传 | 平台显示"已提交" |

内部截止时间定在官方截止前 2 小时，留出网络和平台出问题的余量。

## 分阶段要点

### 1. 读规则
- 附件2（格式）：摘要一般不超过两页；页码从摘要页开始、页脚居中；正文不得出现身份信息（姓名、学校、队号只写在官方封面）。
- 附件3（Word 模板）：封面、摘要页用官方模板，别自己画。
- 附件4（AI 规定）：每条都要落实。模型和公式要有正式文献来源或给出推导；数据分析用了 AI 要注明；程序头要注释 AI 使用情况；参考文献里不能列 AI 工具。
- 题目里带"高效""稳定"这类要求，要在正文用运行时间、多核单调性等实测证据回应。

### 2. 数据刻画与基线
- 先算下界和结构分类，再选方法：它会告诉你瓶颈在哪里（2026A：依赖结构几乎不限制并行，差距来自通信与同步）。
- 基线必须够强。官方示例程序往往不是基线，2026A 的示例在 case_010 上比单核还慢。
- 下界先按乐观口径算，再补一个含同步代价的"可达参考"。零通信下界会让人误判还有多少提升空间。

### 3. 方法
- 没有一种算法能通吃，就做"多构造 + 逐用例选优"，再加后处理（合并、局部搜索、交叉复评、核数补齐）。
- 2026A 的实测：构造方法贡献的提升比局部搜索高一个数量级。工时应该压在构造方法上。
- 失败的路线和原因要记下来并写进论文，这是可信度的来源。

### 4. 冻结与复评
- `finalize`：对每个（问题, 用例, 核数）选出最优方案，用官方评估程序重评一次，保存方案文件、哈希和摘要；`verify_delivery` 逐项核对 CSV、曲线和哈希。
- 冻结前把正式目录备份进 `archives/`，再建一份独立恢复副本，并校验 zip 和 SHA256。

### 5. 写论文
- 目录骨架：问题提出 → 问题分析 → 模型假设 → 符号说明 → 模型的建立与求解（每问分"求解思路 → 模型建立 → 模型求解与结果分析"）→ 模型检验与灵敏度分析 → 模型的评价与推广 → 参考文献 → 附录。
- 第 2 节"问题分析"只讲思路，不出现结果数字。假设每条一句。符号表按类分组，正文用到的符号都要收录。
- 命题宁少勿滥，每条都要紧跟证明；自己提出的公式后面一两句讲清推导（附件4 第 3 条）。
- 摘要每问一段，按"方法—关键数字—结论—适用条件"的顺序写。段首"关于问题一："和各问 2–4 个关键结果数字加粗。开头一句交代问题框架，结尾一句交代验证方式。
- 图：一张图回答一个问题，打印尺寸下能看清。流程图每个框写本题特有的方法或符号，不写空泛短语，不堆"输出：……"行和免责话。彩色没问题。
- 写作细则见 `references/02`、`05`、`06`；分节润色可用 `references/07_分节润色提示词.md`。

### 6. Word/WPS 交付与队友改稿
- LaTeX 转 Word：案例里的 `case-2026A/research/make_docx.py` 负责解析 aux 编号、pandoc 转换、套官方模板封面、设置附件2 字体。转出来以后就交给队友在 WPS 里改。
- 队友每次回传：先用 `docx_tools.py stats` 对比公式、图、表数量，再逐段 diff，重点查以下几类问题：
  - 机械替换造成的错误，例如"题目附录"被改成"附录"、"官方配置"被改掉；
  - 逻辑被改反；
  - 缺主语的病句；
  - 代码被改动；
  - AI 说明被改得和事实不符。
- 批注逐条决定采纳或不采纳，不采纳的要写理由。处理完用 `docx_tools.py strip-comments` 删除批注。
- 目录单独成页用 `docx_tools.py toc-break`。之后必须在 WPS 里右键目录，选"更新域"刷新页码。

### 7. 合规
- AI 说明分四部分：所用工具（名称、版本/型号、开发机构、颁布日期、使用日期）→ 使用环节与目的 → 使用方式（队员决定什么、工具做什么）→ 采纳、人工修改和核验情况。模板见 `references/08_AI使用说明写法.md`。
- 可以突出"思路和取舍由队员决定"，但工具实际做过的事（写代码、生成初稿等）不能写成没做。
- 每个程序文件开头都加 AI 注释（格式见 `scripts/check_code_ai_header.py`），版本号和颁布日期要写全。

### 8. 提交包
```bash
python3 scripts/clean_meta.py 论文.pdf -o 最终/队号.pdf          # 清作者等属性（WPS 昵称会写进 Author）
python3 scripts/submission_check.py 最终/队号.pdf --identity 学校 队号 姓名1 姓名2 姓名3
python3 scripts/page_budget.py 最终/队号.pdf                    # 篇幅体检
unzip -t 附件程序.zip && shasum -a 256 最终/*                   # 完整性与校验和写进提交清单
```
最后把提交包和可编辑源文件复制到独立位置，再上传。以平台显示"已提交"为准。

## 有证据的评审口径（2025 年 21 篇优秀论文实测）

| 问题 | 结论 |
|---|---|
| 正文用"我们"还是"本文" | 21 篇都用"本文"，20 篇也用"我们"，混用是常态；A 题 4 篇中有 2 篇在摘要里写了"我们"。不用为此全文替换 |
| 彩色流程图会不会减分 | 2025 A 题有流程图的 3 篇中 2 篇是彩色的，而且更饱和。颜色不是问题，空泛的框才是 |
| 代码放不放论文附录 | 2025 A 题 4 篇都附了源程序；附件程序单独提交时，正文附录也可以不放 |
| 数字差距 | 同题优秀论文的结果最多差 24 倍，说明建模、分析和呈现占很大权重。但评估标准化以后（如 2026A 有官方评估器），数字的权重会上升 |

## 脚本（`scripts/`）

| 脚本 | 作用 |
|---|---|
| `submission_check.py` | PDF 体检：作者属性、字体嵌入、残留文本、封面外身份信息、目录页码、页脚页码、摘要页数 |
| `clean_meta.py` | 清空 DOCX/PDF 作者等属性，另存新文件（PDF 整体重写，不留增量残留） |
| `docx_tools.py` | `stats` 统计公式/图/表/批注/人称/作者；`toc-break` 让目录单独成页；`strip-comments` 删除批注 |
| `paper_lint.py` | 论文文本检查：AI 腔词、空泛论断、节奏、笔误、合规 |
| `check_code_ai_header.py` | 检查程序文件开头的 AI 注释 |
| `page_budget.py` | 统计正文页数、图、表、公式数，对照篇幅目标 |
| `figstyle.py` / `fig_examples.py` | 数据图的统一风格和 7 类示例 |

`templates/过程图模板/`：6 张 TikZ 过程图（技术路线、由浅入深阶梯、算法流程、预处理流程、变量影响、双层结构）。
